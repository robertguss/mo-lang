## Private operator configuration and Book identity

Use a private bounded operator configuration file, not a token-valued CLI flag.
It holds wire version, fixed loopback port, external run ID, workspace UUID and
capability token. The trusted launcher writes it0700-parent/0600-file outside
candidate and Book roots. Mo reads it before dispatch with a bounded Fs read;
its path is an operator input. No credential enters argv, goal, model Request,
Book args/results, report or retained test logs. A token hash can identify test
configuration. This is an operator provisioning boundary, not a new secret-store
implementation or adversarial local-file containment promise by Mo.

Existing Book.Create chooses the run ID (coding-fixture.mo:59-66), while the
HTTP listener is already bound to an external ID before readiness. Use a fresh
operator Book root and explicit expected external ID; after Create, require
record.id to match that expected ID before Configure/Begin or any tool request.
Reject an occupied/reopened root for this one-run mode instead of adopting or
retrying it. Do not parse Book files in Python or add a Book ID override.

Book still needs a work/ placeholder (Filing requirement). That directory is
not the candidate source. Put conflicting read/write canaries there during tests
to prove all application tool effects occur remotely. Operator files must never
be added to model context merely to make configuration convenient.

## Budgets and dispatch

Keep serialized Budget/Order shapes and validators:16 steps,4096 synthetic
tokens,wall900000,retries0,tool2000. A trusted application factory uses exactly
list_files/read_file/search/write_file/exact_edit/command. Keep legacy order()
rejection of command/exact_edit and fixture policy unchanged.

One outer application deadline900s includes startup, work and reporting. Before
Begin derive work time from remaining minus the shared15000ms report reserve;
refuse if none remains. Begin receives this derived work deadline. Configure
retains the outer report deadline, with the existing shared diminishing grace
accounting (run.mo:73-120), not15s reset per step. Add profile/candidate/wait caps
to versioned report metadata because the unchanged legacy header cannot express
them. Work ending early does not authorize a fresh900s or fresh15s allowance.

Model and file waits stay≤2000ms. Command RPC wait≤300000ms; command execution
request≤120000ms, independently clamped before dispatch to remaining work time.
Refuse when remaining candidate allowance is below the HTTP minimum500ms.
These are configured admission/wait budgets, not proof execution starts or
cleanup completes within an absolute lease across inherited blocking locks.

Before HTTP, validate grants, exact tool args and bounded JSON request encoding.
The model supplies only tool args; timeout, run/call identity, endpoint and token
come from trusted configuration/Run. Tool call ID is the next Book step number,
validated against the HTTP alphabet. Steps.call_for preserves model args without
injecting operator credentials (steps.mo:150-181). Record every observed outcome
once before any subsequent model/tool dispatch.

## Result, failure and reporting semantics

Follow the accepted bridge schema and enum exactly after it freezes. Keep full
wire identities and body bounds in the adapter check. Never pass Python private
manifest/observation or raw ownership documents to the model. Preserve combined
truncation, nullable timing, real exit/signal and strict UTF-8 encoding failures.
No fabricated zero, replacement characters or not_started after uncertain effects.

A valid completed command with exit1 is useful repair feedback, not a terminal
transport failure. A malformed response, unknown execution, invalid execution
proof, lost acknowledgement or closed bridge admission must stop new dispatch.
Use explicit envelope fields for refusal classification; text containing the
word refusal is not evidence. Final terminal classification awaits the frozen
wire enum rather than guessing mappings from the inert fixture adapter.

Application watcher must use the actual deadline, not fixture2250 iterations.
Wait for terminal Book AND Run.Stopped, obtain remaining ReportDeadline and
reread the final record/transcript. Cancellation totals stay unknown/null, while
recorded positive per-call usage remains. Longer synchronous command wait can
increase cancellation latency. Run.Stopped proves Mo dispatch completion only;
operator cleanup/verifier receipt separately proves external cleanup.
