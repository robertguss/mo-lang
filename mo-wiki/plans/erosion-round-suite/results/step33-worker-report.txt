  Decisions the brief did not cover

  1. The state is still rendered twice per crash. It can't share one rendering: the
     invariant's value is the state after the batch and the report's snapshot is the state
     before it, two different values. So a crash still writes 27 MiB (20k jobs) or 140 MiB
     (100k) to stderr.
  2. Ring crash events read their text from the crash store. Once the store has let that
     report go, or with --crashes 0, the event's clause, message and state are empty. The last
     10 events a failed seed prints always fall within the store's 16, so nothing printed is
     lost.
  3. mo test is unchanged. It still keeps every report whole (the runner prints the first
     one). Under mo run, sim.crashes is no longer filled and the C runtime no longer keeps a
     first report, since nothing reads them there.
  4. Small reports are still kept. Runtime failures, mailbox-full and held-send reports hold a
     short formatted clause (and mailbox-full a rendered message); these are not freed. Only
     process-crash values, message log and state go through the freed memory.
  5. C uses its own mapped chunks instead of malloc. malloc_zone_pressure_relief was tried
